# Templates — fill-in scaffolds

Reusable scaffolds the skill instantiates. Copy the shape, replace the brackets, cut what
doesn't apply. These are software/dev-leaning defaults; swap surfaces per
`anchoring-and-cadence.md` for non-SaaS.

---

## Objective statement (the anchor — do this before anything else)

Every launch plan names **one primary objective**. It sets the success metric, the
channel emphasis, and how the tier is read. At most one secondary. If a plan is trying to
serve two masters (e.g. long-cycle enterprise pipeline *and* self-serve activation), it
will build two half-launches — force the choice.

Pick one primary from:

| Objective | The launch is really for… | Primary metric it implies |
|---|---|---|
| **Net-new demand / market creation** | Making a new audience aware a category exists | New-segment reach → qualified interest |
| **Adoption** | Getting the existing base to use the new thing | Feature activation / usage of existing users |
| **Acquisition** | Winning new logos / users | New signups → activation → conversion |
| **Expansion revenue** | Upsell / cross-sell into existing accounts | Expansion pipeline / seats / tier upgrades |
| **Credibility / proof** | Investor, partner, category-authority signal | Named conversations, inbound, press/creator pickup |
| **Competitive defence** | Neutralising or unblocking against a rival | Deals unblocked / win-rate on the contested axis |
| **Validated learning** | *Finding out* if a bet is real (no validation yet) | A pre-committed learning signal, not revenue |

```markdown
## Objective
- **Primary:** [one of the above] — [one line: what winning looks like in 30–60 days]
- **Secondary (watch, not target):** [optional]
- **Explicitly NOT this launch's job:** [what we will not judge it on — protects a
  learning launch from being measured on a revenue standard it can't hit yet]
- **Primary success metric:** [derived from the primary objective, set now, before launch]
- **Conversion path (hypothesis if unproven):** [engagement → next step → commercial
  motion, e.g. free-tool use → evaluation call → contract]
```

A launch with no validation almost always wants **Validated learning** as its primary,
with the commercial metric demoted to a secondary watch — otherwise a scrappy proof-launch
gets declared a failure on a number it was never going to hit in the window.

## Message house (one page)

Value-prop *phrasing* is the highest-leverage decision on this page (Luke Harries). Spend
the effort on the words, not the layout. If it needs real craft, hand to `copywriting` or
your own voice pass.

```markdown
## Message house — [release]
- **Name:** [product/feature name — flag if unresolved]
- **Audience:** primary = [who]; secondary = [who]
- **One-liner:** [the single sentence someone repeats to a colleague]
- **Primary value prop (in the phrasing to use):** [benefit, their words not ours]
- **Secondary value prop:** [...]
- **Bonus value prop:** [...]
- **Proof point (required for T1/T2):** [the demonstrable evidence the claim is true —
  demo, benchmark, side-by-side, named customer. A T1 with no proof point is not a T1.]
- **Objection pre-empt:** [the obvious "yeah but…" and the honest answer]
```

## Rollout countdown

Work back from launch day. Beta / early-access is a real stage where the surface allows
it — the listening stage that fine-tunes messaging and sources testimonials, and the place
a risky release earns its go/no-go.

```markdown
## Rollout countdown — launch day = [date/window]
- **Beta / early access:** [who's in, what we're listening for, testimonials to source]
  - **Go/no-go gate:** greenlight public launch if [signal]; slip or narrow if [signal].
- **L−[n]:** [message house + proof point locked; assets in draft]
- **L−[n]:** [creators seeded & briefed; directory/PH assets ready; internal enablement live]
- **L−[few days]:** [dry run; sales/CS/support briefed; launch-day distribution list named]
- **Launch day:** [the named, ordered fire — who posts what, where, when]
- **L+[n]:** [squeeze begins]
```

Two things this scaffold forces that teams skip: a **go/no-go gate** out of beta (so
"we'll learn in the beta" has teeth), and a **named launch-day distribution list** — the
specific people/threads/accounts posting, not "dev channels" in the abstract. Earned
channels (creators, communities) are not owned; if no name is against them, they won't
happen.

## Internal launch — hit list

Not an explanatory note — a list of items, each with the reason it earns its place. Scale
the list to the tier (full for T1, three lines for T2, one line for T3). See
`tier-menus.md` for the per-tier versions.

```markdown
## Internal launch
| Item | Owner | Why it's on the list |
|---|---|---|
| Sales brief (what / who-for / one-liner / demo) | | Consistent description, no freelancing |
| Objection-handling / FAQ | | Kills the stall on live deals |
| CS / support note + known issues | | Support isn't blindsided |
| Exec / founder talking points | | Loudest voices stay on-message |
| #amplify kit (one-click posts + assets) | | Team socials actually fire |
```

## Post-launch window (launch day = the start line)

Launch day is the starting gun, not the finish — most reach, learning and conversion land
in the weeks after. Plan the window as a sequence, sized to the tier (a T1 sustains for
weeks; a T3 for a few days). Don't front-load one day and taper to zero.

```markdown
## Post-launch window
- **Squeeze / repurposing (agent-flagged):** [long-tail variants; the agentic dividend
  turns one launch into many touches]
- **Second wave (reception-driven):** [what the audience reacted to becomes the next
  content — amplify testimonials/builder posts as they land; turn top questions and
  objections into follow-ups; lead with the proof point that resonated. Highest-signal
  content on the plan, because it's written after you know what lands.]
- **Follow-through sequence:** [L+few days / L+1wk / L+1mo — the touches that keep the
  release marketed instead of dropping to zero]
- **Ongoing internal use:** [enablement isn't one-and-done — sales/CS still using it weeks
  later]
- **Success metric (from the Objective, set before launch):** [...]
- **Vanity-metric watch:** [the number that will tempt us and mislead us — name it]
- **Retro trigger:** [when we look back, and where the learning is written —
  `memory/learnings/` / `active/release-roadmap.md`]
- **Hand to campaign-brief if:** [the follow-through becomes an ongoing program with its
  own objective beyond this release]
```
