# Release GTM — references

Deep detail the `release-gtm` skill reads on demand, so the SKILL.md stays a lean
selector. Load the one the current step needs; don't read them all up front.

**What lives here:** the *durable* machinery — the scoring rubric, the tier menus, and
the anchoring/cadence swaps that keep the skill from being SaaS-only.

**What deliberately does NOT live here:** current channel fashions or tool-of-the-month
tactics (which ProductHunt slot converts, whatever the new launch channel is). Those
rot within a quarter. The skill grounds the channel mix in the client's *own* traction
data (`evergreen/channels/`) at runtime, not in a fixed menu here.

Files:

- `rubric.md` — the full score→tier machinery: dimensions and anchors, weights, the
  score bands, the caps/gates, and the roadmap ranking pass. This is the anti-inflation
  engine.
- `tier-menus.md` — the instantiated menus per tier (T1–T4): channel breadth, asset
  checklist, rollout countdown, and enablement — each asset pre-flagged agent-draftable
  vs human. Menus to *choose from*, not to dump.
- `anchoring-and-cadence.md` — how to stretch the skill past B2B SaaS: which parts are
  universal (reach, investment, lead time, channel breadth) and which are software-native
  menus to swap; plus the rolling-thunder cadence model and its limits.
- `templates.md` — fill-in scaffolds the skill emits: the objective statement (the plan's
  anchor), the message house, the rollout countdown (with go/no-go gate + named
  distribution list), the internal-launch hit list, and the post-launch squeeze.

Expandable: if a durable frame is missing, reason from first principles, say it's
missing, and add a file. Keep capability/fashion facts out — ground those in the client's
traction at runtime.
