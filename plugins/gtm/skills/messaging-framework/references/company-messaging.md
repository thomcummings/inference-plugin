## 1. What a Company Messaging House Contains

The company messaging house is the hub for all approved company-level copy. It serves marketing, sales, PR, partnerships, recruiting, and leadership. Everyone in the company should know it exists and use it.

### Components

```
COMPANY MESSAGING HOUSE
├── How to Use This Document (usage guide for internal teams)
├── Descriptions (boilerplates at multiple lengths)
│   ├── Short (1-2 sentences)
│   ├── Medium (3-4 sentences)
│   ├── Long (1-2 paragraphs)
│   └── Press Release Boilerplate (third person, formal)
├── Value Propositions
│   ├── Short (1 sentence)
│   └── Long (2-3 sentences)
├── Brand Copy (emotional, story-level)
│   ├── Purpose statement
│   ├── Vision statement
│   └── Mission statement
├── Facts & Proof Points
│   ├── Key metrics
│   ├── Awards & recognition
│   └── Customer evidence (logos, quotes with consent status)
└── Parking Lot (retired messaging, archived for reference)
```

### Design Principles

**Copy-paste ready:** The grey boxes (or equivalent formatted sections) should be directly usable. Teams shouldn't need to rewrite — they should copy, paste, and go.

**Clearly labelled:** Every piece of copy should be labelled with what it is and when to use it. "Use this for social media bios" or "Use this on press releases only."

**Governed:** There should be clear owners and an update process. Messaging that's nobody's responsibility becomes everybody's liability.

## 2. Building the Description Stack

Descriptions answer: **"What does this company do?"** They're factual, reusable, and relatively stable. They describe the company, not the value it creates (that's value propositions).

### The Short Description (1-2 sentences)

This is the most important piece of copy in the framework. It's used everywhere — social bios, directory listings, partner pages, event programmes, speaker bios, email signatures.

**Framework:**
```
[Company] is a [category] company [doing what] [for whom].
```

Add a second sentence for the key differentiator or proof point if space allows.

**Quality criteria:**
- Can a stranger understand what the company does after reading this once?
- Does it use category language that the target market recognises?
- Is it under 30 words (ideally under 20)?
- Does it avoid jargon, buzzwords, and insider language?

**Process:**
1. Start with the positioning statement — extract the market category and core activity
2. Draft 3-5 variants
3. Test with the "explain it to a bored-but-smart teenager" standard (Jackson's principle)
4. Select the clearest one, not the cleverest one

**Example (fictional, Ledgerly):** "Ledgerly is accounts-payable software that gets every supplier invoice approved, paid and reconciled without a spreadsheet."

### The Medium Description (3-4 sentences)

Adds one layer of detail — typically who uses it and a key proof point.

**Framework:** Short description + audience/scale indicator + key differentiator or proof point.

**Example (fictional, Ledgerly):** Short description + "More than 4,000 finance teams use Ledgerly to process over a million invoices a month, with the average invoice approved in under two hours."

### The Long Description (1-2 paragraphs)

The full story in compact form. Used on website about pages, detailed partnership materials, and investor communications.

**Framework:** Medium description + how it works + key outcomes.

### The Press Release Boilerplate

A specific format used only on press releases. Third person, formal register. Usually the long description rewritten in third person with the latest awards/recognition appended.

**Key rule:** The press boilerplate should be reviewed quarterly and updated with the latest credibility signals (awards, funding rounds, customer milestones).

## 3. Building Value Propositions

Value propositions answer: **"What value do customers get from working with us?"** They're about the customer's outcome, not the company's activities. Descriptions say what we do. Value propositions say why it matters.

### The Distinction (important — teams confuse these constantly)

- **Description:** "Ledgerly is accounts-payable software that gets every supplier invoice approved, paid and reconciled without a spreadsheet."
- **Value Proposition:** "Close the month in days, not weeks, with every invoice approved on time."

The description is about Ledgerly. The value proposition is about what Ledgerly makes possible for the customer.

### Short Value Proposition (1 sentence)

**Framework:**
```
[Action verb] + [what the customer gets] + [qualifying detail] — [outcome].
```

Or the "Now you can ___" test from Language-Market Fit: if the value prop completes that sentence naturally, it's customer-centric.

**Quality criteria:**
- Is the subject the customer, not the company?
- Is the outcome specific, not generic?
- Would a prospect read this and think "I want that"?

### Long Value Proposition (2-3 sentences)

Expands the short version with how and for whom.

**Framework:** Short value prop + how the platform delivers it + scope/scale of what's available.

**Example (fictional, Ledgerly):** "Ledgerly helps finance teams take invoices from inbox to paid without chasing anyone. Approvals route themselves to the right budget owner, and payments reconcile against the ledger automatically, so month-end close takes days, not weeks."

### Value Proposition Quality Checks

Apply Laja's four criteria:
- **Clarity:** Can you understand this in one reading?
- **Relevance:** Does the target persona see themselves in it?
- **Value:** Is the benefit immediately obvious?
- **Differentiation:** Could a competitor say this? If yes, make it more specific.

Additionally:
- **The "so what" chain:** Keep asking "so what?" after each claim. "We route approvals automatically" → so what? → "Invoices stop sitting in inboxes" → so what? → "Suppliers get paid on time" → so what? → "You close the month faster and keep supplier terms." Push until you hit the outcome the customer cares about.

## 4. Facts and Proof Points

### Metrics

Compile all credibility-building numbers. Format them as self-contained statements that can be dropped into any context.

**Categories:**
- Scale metrics (users, customers, usage volume)
- Speed metrics (time to value, response rates)
- Quality metrics (NPS, satisfaction scores, accuracy rates)
- Market metrics (countries, languages, coverage)
- Heritage metrics (founded, years in operation)

**Format each as a standalone copy block:**
```
💬 4,000+ finance teams use Ledgerly
💬 1M+ invoices processed every month
💬 The average invoice is approved in under two hours
```

**Governance rule:** Metrics must be reviewed quarterly. Stale numbers (especially fast-moving ones like user counts) undermine credibility.

### Awards and Recognition

List with dates and reference URLs. These are credibility signals for PR, sales materials, and website badges.

### Customer Evidence

Maintain a consent database. For each customer:
- Can we use their logo externally?
- Do we have an approved quote?
- Is there a case study?
- What's the consent status? (important for legal compliance)

## 5. Brand-Level Copy

Purpose, vision, and mission statements (from the Brand Architecture skill) should live in the messaging house as well, but clearly labelled as **brand-level copy for emotional storytelling**, not day-to-day descriptions.

**When to use brand copy:**
- Keynote speeches and all-hands presentations
- Career pages and recruiting materials
- Investor communications
- Brand campaigns
- The "about" section of the website (alongside, not replacing, the description)

**When NOT to use brand copy:**
- Product pages (use value propositions instead)
- Sales emails (too abstract)
- Social media bios (too long, too aspirational)
- Press releases (use the boilerplate)

## 6. Assembling the House

### Document Structure

Use this structure:

1. **How to use this messaging house** — Brief guide explaining what's in the document, who it's for, and how to use it. Link to related resources (style guide, customer consent database, product messaging houses).

2. **Descriptions** — All length variants, clearly formatted for copy-paste.

3. **Value propositions** — Short and long, clearly separated from descriptions.

4. **Brand copy** — Purpose, vision, mission, with clear labelling about when to use these.

5. **Facts and proof points** — Metrics, awards, customer evidence.

6. **Parking lot / Archive** — Old messaging that's no longer approved but kept for reference. This is important — it prevents people from accidentally resurrecting retired messaging.

### Formatting Best Practices

- Use clearly marked copy blocks (grey boxes, callout formatting, or equivalent) for any text that should be copy-pasted
- Use emoji indicators to distinguish types: 💬 for copy, 💙 for benefits, 👉 for features
- Include a "last updated" date
- Include ownership (who's responsible for keeping this current)

## 7. Maintenance and Governance

### Ownership

The messaging house needs a named owner (typically the Head of Marketing, Head of Content, or Product Marketing lead). Without ownership, it decays.

### Review Cadence

- **Metrics:** Quarterly
- **Descriptions and value propositions:** Every 6 months or when significant product/strategy changes happen
- **Brand copy:** Annually (aligned with strategy reviews)
- **Customer evidence:** Ongoing (add new logos/quotes as they're approved)

### Change Process

- Minor updates (metrics, new logos): Owner can update directly
- Message changes (new value prop, revised description): Requires stakeholder review (marketing + product + sales lead at minimum)
- Brand copy changes: Requires CEO/leadership sign-off

## 8. Common Pitfalls

**No length variants:** Teams create a single description and then everyone shortens it differently. Result: 10 versions of the company description floating around, none approved.

**Descriptions that sound like value propositions (and vice versa):** Keep these separate. "We build X" is a description. "You get Y" is a value proposition. Teams that confuse them end up with messaging that's neither clear about what the company does nor compelling about why it matters.

**Metrics without context:** "200k participants" means nothing to someone outside your industry. Add context: "200k+ active, verified participants" or frame relative to competitors.

**Brand copy used as sales messaging:** Purpose and vision statements are inspiring but not persuasive in a sales context. They're too abstract to drive action. Sales needs functional messaging backed by proof.

**The messaging house nobody uses:** The most common failure mode. The document exists but teams don't reference it. Solutions: make it findable (link from key tools and workspaces), make it copy-paste friendly, socialise it during onboarding, and enforce it in content review processes.

**No archive section:** Without a parking lot for retired messaging, old copy zombies keep resurfacing in sales decks and partner pages months after being replaced.
