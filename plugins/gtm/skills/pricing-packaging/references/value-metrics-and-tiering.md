# Value metrics and tiering

The menu behind steps 1, 5 and 6. Opinionated calls stay in the skill; this is the
accurate catalogue and the honest fit tests so the skill doesn't optimise a metric or
tier that isn't the constraint.

## Commercial object (full)

| Object | Examples | Main pricing risk |
|---|---|---|
| Product subscription | SaaS, AI tool, membership | weak value metric, confusing tiers, bad upgrade path |
| Usage / volume product | API, credits, seats + usage, data product | value-metric misfit, bill shock, margin leakage |
| Productised service | audit, sprint, implementation kit, managed advisor | hours disguised as value, scope creep, weak responsibility boundary |
| Advisory / retainer | fractional CMO, expert access | vague value, unlimited access, margin erosion |
| Premium implementation | agent team, bespoke workflow, agency alternative | under-anchoring against SaaS instead of headcount/agency replacement |
| Hybrid | software + expert escalation + implementation | collapsed tiers, unclear who owns the outcome |

## Value metric candidates (product / usage)

- seats / users
- active customers / accounts / projects
- volume processed (requests, records, minutes)
- revenue managed / GMV
- campaigns, workspaces, brands, products, integrations
- outcomes / transactions
- managed time / capacity

## Value-metric fit tests

Score a candidate metric against all six before recommending a switch:

| Test | Good | Bad |
|---|---|---|
| Value alignment | rises as the customer gets more value | charges for things unrelated to value |
| Budget fit | maps to how the buyer budgets | crosses budget lines / needs new approval |
| Predictability | buyer can forecast the bill | surprise bills, bill shock |
| Margin | scales with, or ahead of, cost-to-serve | cost outpaces revenue |
| Expansion path | grows naturally with customer success | flat, or punishes adoption |
| Abuse risk | hard to game cheaply | easy to under-declare or share |

Rule of thumb: a metric that punishes adoption (e.g. per-seat on a tool everyone
should use) suppresses the very behaviour that drives value and expansion. Prefer a
metric that expands with success.

## Tier logic — responsibility contract, not feature list

Two to four tiers. Every tier needs a distinct buyer state, an upgrade trigger and a
responsibility boundary. If two tiers differ only by a feature checkbox, merge them.

| Tier type | Customer contract | What changes |
|---|---|---|
| Self-serve / Core / BYOK | Customer operates | frameworks, cockpit, templates, BYOK compute, limited support |
| Advisor / managed | Shared responsibility | managed advisor, cadence, context, bounded escalation, fair-use usage |
| Agent Team / premium | Provider takes more responsibility | specialist network, custom workflows, richer integrations, higher-touch delivery |

Generalisations that hold outside any one company:

- DIY → guided → done-with-you → done-for-you
- tool → workflow → managed outcome
- template → diagnostic → implementation sprint → retained operating layer

## Tier failure modes to watch

- **Cannibalisation** — the cheap tier does enough that no one upgrades.
- **Tier cliff** — the jump in price is not matched by a jump in perceived
  responsibility taken off the buyer.
- **Hidden support load** — a low tier that quietly consumes senior time.
- **Unclear premium value** — the top tier reads as "the same, but more", not "we now
  own more of the outcome".
- **Legend required** — if buyers need a comparison sheet to understand the plans, the
  packaging is harming conversion.
